# 2D screens of Dark Cloud (USA): HUD, pause menu, item / weapon / synthesis rules

Research for the native port (2026-10-19). Everything here was read from `work/decomp/all_dun.c` (Ghidra decompile of SCUS_971.11 + the dungeon overlay DUN.BIN) and the game's data files; every statement is tagged
**VERIFIED-DATA** (read from a data table / file), **READ** (read from decompiled code), **CHECKED** (re-drawn with `tools/dc/hud_mock.py` and compared by eye) or **INFERRED** (a guess, to be confirmed).
Companion notes written by parallel agents: `notes/menus_shops.md` (item shop, charge shop, Atla menu, inventory limits) and `notes/menus_screens.md` (option, save/load, name registration, manual, dungeon entrance, quick change, title).

## 0. Conventions and tools

* **Screen**: logical **640x448**. The game draws into a 640x224 field buffer: `set2DSprite` writes `x*16 + 0x6c00`, `y*8 + 0x7900` (so y is halved when drawn; the TV shows it again as 448 lines). A sprite with dst height h and src height h is therefore shown 1:1 on a 640x448 picture. READ (`set2DSprite @0x15c310`).
* **Sprite call** `set2DSprite(packet, texture, dst{x,y,w,h}, src{x,y,w,h}, alpha)`; `DrawMenu2DSprite(texture, dst, src, alpha)` is the menu wrapper (@0x22cf20). src and dst sizes are independent (the sprite is scaled). PS2 alpha 0x80 = fully opaque (so `alpha & 0xff` up to 0x80; values above are clamped by the GS). Some menu helpers draw `dst.h = src.h - 1` (a one line trim). `set2DSpriteC4(rect, c1, c2, c3, c4)` = flat quad with 4 vertex colours (order TL, TR, BL, BR); `MGFillBox(rect, r,g,b,a)` takes its rect in **1/16 pixel of the 640x224 field** (x*16, y_field*16, w*16, h*16).
* **Pad masks** (CGamePad::Down/On): 0x10 triangle, 0x20 circle (= cancel), 0x40 cross (= OK), 0x80 square, 0x1000 up, 0x2000 right, 0x4000 down, 0x8000 left (so 0x9000 = up|left, 0x6000 = right|down, 0x5000 = up|down, 0x3000 = up|right, 0xc000 = down|left), 0x60 = cross|circle; shoulder pairs: mask 0x5 = L1|L2, 0xa = R1|R2, 0xf = any. READ.
* **Files** (the USA game loads `commenu/` + country dir + name, `LoadFileMenuData` @0x22bb40; country dir `a_usa/` for LanguageCode 1; `GetPathReadDifferntLang`). All textures are TIM2 inside IMG/IM2 containers inside `.pak/.pac` packs; decode with `tools/dc/ui_dump.py` (writes PNG + contact sheet to `work/ui/`), `tools/dc/img.py` (IM2 = swizzled 8-bit). Helper scripts of this research: `tools/dc/ui_dump.py`, `ui_view.py`, `rects.py` (every sprite draw of a function as dst/src rects), `hud_mock.py` (HUD re-drawn from the tables below), `mem.py` (read ELF/overlay data by address), `decomp_index.py` (find/show/callers/strings over the decompile), `menu_mes.py` (message banks).
* **Message banks** (menu text): `a_usa/dungeon/dunmenu5.pak:allmenu.mes` (the main menu bank, also copied in `emenu.pak`, `option.pac`, `savetex.pak`), `atrames.bin` (Atla texts), `meswin/_systeme.bin` (system text). **Bank format correction**: `short[0]` is the number of `{id,offset}` entries (NOT the number of shorts); text of an entry starts at short index `short[0] + 1 + offset`; messages end with 0xFF01. `native/dccore/src/text.cpp` (`2 * i < table`) and `tools/dc/mesdump.py` only read the first half of every bank (for `_systeme.bin` ids 377..3079 are lost, for allmenu.mes ids 541..793 incl. all weapon/item descriptions). Use `tools/dc/menu_mes.py`. VERIFIED-DATA (`_systeme.bin`: 633 entries, ids ascending to 3079; allmenu.mes: 495 entries, ids to 793).
* The decompile labels the dungeon overlay badly (MoveChara contains labels called DrawMess / MainDraw / CMajinBeem::Step / CSeireiKing::Draw ...; boss-overlay symbol names overlap DUN.BIN). The dungeon's per-frame 2D draw is the code labelled `MainDraw @0x1dae2a0` (lines 171719-172530 of all_dun.c); the same block is repeated for other game modes (lines 172900+).

### A.4 Colours, alarm, constants (READ + VERIFIED-DATA)
* `Pal(max,cur,weapon)`: `0.2*max < cur` -> normal colour (`life` or `weapon`); else if `0.3*max < cur || cur <= 0.15*max` -> "15" colour (red); else "30" colour. Left/right vertex colours (RGBA, alpha 0x80) from `BtStatusAlarmInit @0x1b0260`: life (0x40,0xc1,0x82) -> (0x00,0x81,0xff); weapon (0xff,0x80,0x00) -> (0xff,0x20,0x00); "30" (0xff,0x00,0xc6) -> (0x3f,0x00,0x31); "15" (0xff,0,0) -> (0x3f,0,0) (the 15-colour alpha pulses: `0xc0 - ...`).
* `statusAlarmRate` (the `al` alpha): `BtStatusAlarmAnime @0x1b0320` each frame: `counter += 0.10472` (2*pi/60, wraps at pi? `DAT_002a18a0 = 3.14159`); `al = 0xc0 - int(sin(counter) * 128)`; used for a gauge frame when life/durability <= 20% (`0.2*max >= cur`) and for the water block when `cur <= 0.15*max`; otherwise alpha 0x80. Initial value 0x80.
* Gauge scales: life 0.74 px/HP, weapon 1.49495 px per WHp point. VERIFIED-DATA (0x2a1e00, 0x2a1e04).

### A.5 Attack gauge (`MainDraw` 172334-172390; value `DAT_01dc44c8` float 0..100, flag `DAT_01dc44cc`)
* value >= 100: full strip dst (0x28, 0x18c, 128, 28): src (0, 0, 128, 28) (blue) when `DAT_01dc44cc == 0`, else src (0, 0x1c, 128, 28) (pink). INFERRED: the flag is an "overheat / locked" state (Osmond's machine gun uses `DAT_01dc4524`, the swing code sets `DAT_01dc44cc`; see native-plan Milestone 4).
* value < 100: empty strip dst (0x28, 0x18c, 128, 28) <- (0, 0x54, 128, 28), then the fill dst (0x42, 0x18c, v, 28) <- src (0x1a, 0x38, v, 28) with v = int(value) (so the fill is v pixels wide: 1 px per gauge point).
* alpha for all = `(rogoY3 + 0x60) & 0xff`.

### A.6 Ailment tag (`BtStatusErrDraw`, status word of the active character: `UserStatus + 0x42c8 + 4*char`)
For bit in (0x40 Goo, 0x20 Curse, 0x10 Poison, 8 Stamina, 4 Freeze) (drawn in this order, later ones on top, ALL at the same place): dst (0x1ae, y0, 62, 35) <- itempack (0x84 + 62*col, 0x54 + 36*row, 62, 36) with (col,row): Freeze (1,0), Stamina (0,1), Poison (1,1), Curse (1,2), Goo (0,2). The (0,0) cell is a blank tag. VERIFIED-DATA (tables 0x26b070 / 0x26b090). Set/clear rules `BtSetStatusErr @0x1b1bb0`: 0x40 only if none of 0x1c is set; 0x20 always; 0x10 only if none of 0xc (and clears 0x40); 8 only if not frozen (sets timer short `+0x42e0 + 2*char` = 0x708 = 30 s); 4 sets 4, clears 0x58, timer = 300. Poison damage `BtStatusErrStep`: every 180 frames lose int(0.1*maxlife) (const 0x2a1860 = 0.1) READ.

### A.7 Mini map (`DrawMiniMap @0x1c3180`; option `UserStatus+0x433c` = map mode 0..2 (density), 3 = off)
* Grid 20 x 20 cells of 160 world units; screen tile (col, row) at (0x17c + 16 col, 0x40 + 16 row) 16x16 (so the map hangs from (380, 64)); world->map scale 0.1 px per unit (VERIFIED 0x2a1870).
* A cell is drawn if its `visited` flag (`map + 0x8710 + 4*cell`) == 1, or the Map item is equipped (`BtEquipMap`, then flagged as visited-looking but dimmer); tile index = `cell.tile (map + 0x9c54 + 16*cell) + partTileBase (short at part*0x1d0 + map + 0x490)` (skipped when `cell.part (map+0x9c50+16*cell) == -1`); atlas cell (idx & 7)*16, (idx >> 3)*16 of `minimap<N>`. Tint for mode m: explored RGB = {0x60,0x80,0xa2}[m], unexplored-but-Map RGB = {0x20,0x40,0x60}[m], alpha = {0x40,0x60,0xa2}[m] (VERIFIED-DATA 0x2a1fc0).
* Markers (itempack): player arrow, rotated with the camera (`set2DSprite(...,rot)`): src (0x58,0x60,12,12) at (x*0.1 + 380 + 8, z*0.1 + 64 + 8); 3 entries (struct at map+0x10ab0, stride 0x20): 8x8 src (0x58,0x70) cyan dot (INFERRED: exits / stairs); 24 entries (map+0xb660, stride 0x40): src (0x50,0x60) red dot (monsters); 8 entries (map+0xbc80, stride 0x20): src (0x48,0x68) orange dot (items/treasure). Dots at (x*0.1 + 0x180, z*0.1 + 0x44); only shown on a cell that would be drawn (visited, or crystal ball `BtEquipMasuisyou == 1` shows all).

### A.8 Floor banner (`rogoSwitch2`, set by script ext `_SET_FLOOR_TITLE` -> `FloorTitleOn @0x1dc1290`; ends with `_SET_FLOOR_TITLE_OFF`)
State `startCnt2`: 0 fade in (alpha `DAT_01eb3ab8` += 4 up to 0x80, then `DAT_01eb3ac8 = 0x78`), 1 hold (counter -1 per frame = 2 s), 2 fade out (alpha -= 4), 3 end (`rogoSwitch2 = 0`); the HUD slides in meanwhile (+2/frame). Texture `floorNN` (US set): for the main layout (LanguageCode > 0) the "LIMITED ZONE"/level row src (0, 0x78, 0xf0, 0x30) -> dst (0xd4, 0xe6) (back dungeon: src (0x110, 0x78, 0x60, 0x38) -> (0x110, 0xe6)); floor number digits 38x50 <- src (d*0x26, 0x32, 0x26, 0x32): one digit at (0x15a, 0xaa), two digits tens (0x136) units (0x15a), three digits hundreds (0x112) tens (0x136) units (0x15a); the number shown is floor+1, except dungeon 5 which uses `BtGetFloorLevel(floor)`. Dungeon-specific name plate (src (0,0,w,50) at y 0xaa, a per-dungeon switch at 0x1daf9e4..0x1dafce0: dungeon 0 w=0x2d @ (s1+0x122), 1 w=0xda @ 0xa0, 2 w=0x91 @ 0xc8, 3 w=0x8e @ (s1+0xdc), 4 w=0x4b @ (s1+0xc3) + extra (0x60,0,0xc0,0x32) @ 0x13b, 5 w=0xe1 @ 0x108, 6 w=0x8e @ (s1+0xdc); `s1` is -0x24 when floor >= 9 else 0). READ (disassembled switch); Japanese set uses another table (0x1daf5c4..). The alpha of every banner sprite is `DAT_01eb3ab8`.

### A.9 Damage numbers (`CHitValue`, 32 slots of 0x60 bytes; `EntryValue @0x1b6370`, `Step @0x1b6850`, `Draw @0x1b6560`)
* An entry holds up to 5 digits (value split by 10000..1, leading zeros dropped), a 3D point (projected with `MGRotTransPers2D`), a type (0, 1, 2) and an alpha. Digit glyph = 12 x 18 <- `stayframe` (digit*12, row, 12, 18), row y = 0x9e (type 0, white), 0x8c (type 1, yellow), 0x7c (type 2, red); the units digit is drawn at the projected x, the others to the left in steps of 12; y of digit i = `screenY - int(sin(phase_i) * 48) - 0x30`. Each digit has its own phase starting at -pi (`DAT_002a1d18`), +`pi / (5 i + 20)` per frame (so digit i hops for 40 + 10 i frames: a full sine dip-and-rise, ends at pi); a type-"no effect" entry (value -1) is the sprite `NoEffect` (itempack (0, 0x80, 72, 24)) with its phase advancing 0.15708/frame. Alpha: `+0x3c` rises by `+0x40` = 3.0 per frame to 128; when the last digit's phase reaches pi the rate is multiplied by -1.2 (`DAT_002a1da4`) and the alpha falls to 0, then the slot is free. READ.
* Hidden by options (`CSaveData::GetConfigData`, field map in `notes/menus_screens.md`; the float compares in the decompile are the integers 2 / 0 / -1): type 2 (red row) = damage to the party, hidden when config `+0x24 == 1` ("Player Damage Display", message 358); type 0 (white row) and -1 (`NoEffect`) = damage to monsters, hidden when `+0x28 == 1` ("Enemy Damage Display", message 357); type 1 (yellow row) is never hidden (items/gold; INFERRED). The enemy HP bar uses `+0x2c == 0` (A.10).

## C. Item / weapon / status rules

Data layout used below (UserStatus = `CDngStatusData`, byte offsets; ported in `native/dccore/include/dccore/user_status.h`, `items.cpp`):
`+0x4360` bag capacity (signed char, 50 at start, +10 per Pocket up to 100), `+0x4362` 3 x s16 quick-slot item ids (-1 empty), `+0x4368` 3 x s16 quick counts, `+0x436e` 0x67 x s16 bag item ids, `+0x443c` 0x67 x s16 bag values (uses / minutes), `+0x8b14` 3 x s32 per quick slot extra, `+0x4348 + 4c` defense of character c, `+0x42c8 + 4c` status flags (A.6), `+0x42ec/+0x4304 + 4c` water max/cur (float), `+0x12 + 2c` life, `+6 + 2c` max life, `+0x4346` gold (u16, max 65535), `+0x450c + 0xaa8 c + 0xf8 s` weapon records (11 slots per character), `+0x4340 + c` equipped slot, `+0x84fc + 0x20 i` attach list (0x2b = 43 records; the menu refuses new attach items at 40: message 162), `+0x433c` map mode option, `+0x8b10` zone limit code (0..5 limited zones, 10 = weapon-limited), `+0x431c` "bag overflow / item-throw" flag.

### C.1 Item page (`ItemMenuMainKey @0x202f10`, `ItemMenuModeDraw @0x2059b0`, `ItemMenuCharaStatusDraw @0x206b40`, boards `PersonalBoard*`)
* Screen areas (`ItemMenuMode`): 0 = the 3 **active item** slots (header "ACTIVE ITEM" from `wepchara.img:status`), 1 = **character panel** (face, life bar, thirst bar, defense number; drop target to use an item on the character), 2/3 = weapon / "attachment" drop targets inside the panel, 4 = the **board** (5 columns x N rows grid of the bag, scrolling `DAT_01d9ec28` rows; `DAT_01d9ec14` = which board: 0 items, 1 weapons, 2 attach items), 5 = the trash can. Navigation: d-pad inside the area, up/down/left/right moves between areas; L1/L2 (0x5) previous / R1/R2 (0xa) next character (`ChangeMenuChara`, only among the party `UserStatus+5`), triangle (0x10) = "quick move": moves the item under the cursor to the first free/matching quick slot (stack limit below), square (0x80) = tidy the board (`SeitonAttachBoard`, sorts), circle drops the held item back / exits.
* The UI is "pick up and drop": cross picks up the item under the cursor (`BtlHaveItemPt`, held icon follows the cursor; `held[0]` remembers where it came from: 0 = an active slot, 4 = the board, 5 = the trash can; circle puts it back there) and drops it on the target under the cursor:
  * **on the 3 active slots**: allowed only for items whose ITEM_LIST kind (`+0x10`) is 0 (stackable consumable: same id stacks up to **9** per slot, `count > 8` is refused; a different id replaces the slot's item only if the slot holds a single piece) or 1 (unique, e.g. amulets, Revival Powder, Auto Repair Powder, Dran's Feather: replaces a slot that holds <= 1 piece of a stackable item or another unique item); kind 2 (key items, powders ...) is refused (beep). The replaced item goes back to where the held one came from.
  * **on the character** (`ItemUseFunc @0x20c3e0(status, itemId, character, mode 1)`): see C.2; `return 2` / table value 2 = "no effect" -> beep and the item stays.
  * **on the weapon**: only Repair Powder (0xb1) and Powerup Powder (0xb2), C.3.
  * **on the trash can** (`ItemTrushKey`, `IsEnableTrushThrow @0x2311a0`): items with ITEM_LIST flag16 (`+8`) bit 0x10 set cannot be thrown away (keys, quest items, Pocket, Fruit of Eden, Gourd ...: all rows with flags `0x18/0x11/0x8` in `work/tables/items.csv`); attach items can; weapons can unless it is a default weapon (`defWeapon[c]` or `+1`) of any character, or a character outside the party, or Serpent Sword (0x10c) while the hebikiri flag is unset; thrown weapons/attach items are simply deleted.
* The "item overflow" mode: when `GetItem` finds the bag full (`CheckItemGet` = 1) the item goes into 3 spill-over slots right behind the bag capacity (`+0x436e + 2(cap + k)`) and `+0x431c = 1`; the menu opens on the Item page and the player must discard or use items (message 187 "Items full. Move one {icon} to board by discarding or using."); circle is refused until the spill-over slots are empty (`CheckItemThrow`).
* Texts: allmenu.mes ids 180-193 (`180` "Remove everything / Set the same item", `181` "Organize / To active item", `182` "Organize", `190` Trash Can, `191` "Drop item here when used on weapon", `193` "Drag item here when used on character", `189` Defense power), item descriptions = **message id (item id + 500)** of allmenu.mes (e.g. 0xaa Mellow Banana -> 670), weapon descriptions = `ComItemInfo[w].msg + 500`, attach item descriptions = id + 500 (581 = Fire ...).

### C.2 Item effects when used on a character (`ItemUseFunc`; ITEM_LIST fields: `+4` u32 effect flags, `+8` u16 usage flags, `+0xa` s16 value 1, `+0xc` s16 value 2, `+0x10` kind; `work/tables/items.csv` has all 124 rows)
Usage flags (+8): 0x1 usable on a character from the menu, 0x2 status-inflicting item (dungeon only, see below), 0x4 healing item (life/water), 0x8 key / event item, 0x10 not discardable, 0x20 stat-raising item. Effect flags (+4):
* **Heal life** (+4 & 0x40, flag +8 & 4): if `0 < life < max` -> `SetNextLife(life + value1)` (smooth fill; cap by max). Items: Bread 50, Premium Chicken 200, Cheese 80, Mellow Banana (0xaa) +200 and thirst -20 (`AddDrink(-20)`).
* **Restore water** (+4 & 0x80, flag +8 & 4): if `cur + 2 < max`: `cur = min(max, cur + value)` (Regular 30, Tasty 50, Premium 100).
* **Defense foods** 0x88..0x8d (Doughnut .. Cookie): only the matching character (`character == id - 0x88`, else no effect): `defense += value1 + rand() % value2` (5 + rand%3), cap 99; message 404 shows the amount.
* **Cure ailments**: flags 0x4000 (Freeze, bit 4), 0x8000 (Antidote, bit 0x10), 0x10000 (Sacred Water, bit 0x20 curse), 0x20000 (Soap, bit 0x40 goo); Mighty Healing 0x9a (id 154) clears everything except bit 8 (0x74 mask); needs life > 0 and not dead (status bit 2 clear); messages 418 (poison), 419 (curse), 420 (goo), 421 (all). Revival Powder (0xb0) on a dead character: clears statuses, life = max/2.
* **Fruit of Eden** (0xb4): needs `status bit 2 == 0` (alive) and `life > 0`; `max life += 10` up to the per-character cap table at 0x293978 (max life cap per character Toan..Osmond = 170, 140, 170, 140, 180, 160; VERIFIED-DATA); the character is NOT healed, `SetNextLife(0, ..)`; message 405. **Gourd** (0xb6): `waterMax += 10` if waterMax <= 90, cur = max (message 406). **Pocket** (0xb3): bag capacity +10 (only if cap < 0x60), capped at 100 (message 407). Throwing items (Bomb, Stone, Gems ... effect flags 0x1-0x10, 0x100, 0x200, 0x800) cannot be used in the menu (return 0).
* **Status items used on the character in the dungeon** (`BtlMenuMode == 0`, life > 0, not dead): effect bit 0x100 (Throbbing Cherry) sets status 4 Freeze (timer 300 frames; toggles it off if already set), 0x200 (Poisonous Apple) sets 0x10 Poison unless frozen / stamina (clears 0x40), 0x400 sets 0x20 Curse, 0x800 (Gooey Peach) sets 0x40 Goo unless one of 0x1c is set, 0x1000 (Stamina Drink) sets bit 8 Stamina with timer 0x708 (1800 frames) unless frozen; these are the same flags the thrown versions apply to monsters. READ (`ItemUseFunc` tail, `BtSetStatusErr`).
* After a successful use the item is decremented from the bag/quick slot by the menu code (`DeleteItemAfterUseItem`).
* **Escape / Warp / Stand-in powders** are used with the quick-item button in the dungeon (player_items.cpp), not from this page.

### C.3 Repair Powder (0xb1) and Powerup Powder (0xb2)
Both are dragged from the board (or chosen with the "Repair" / "Upgrade" commands on the Weapon page, C.4) onto a weapon.
* **Repair Powder**: allowed when current WHp (`+0x10` float) < max WHp (`+0xc`): sets `WHp = max`; if the weapon is the broken default (`id == defWeapon[c]`) it becomes `defWeapon[c] + 1` (the real default weapon, record rebuilt with `WepDataListToHaveCopy`, level 0); result 2 = success (message 403 + the Repair effect `CureEffect(.., 6)` and sound 0x18). Refused otherwise.
* **Powerup Powder**: allowed if the weapon is NOT the broken default, level (`+2`) < 99 (`psVar[1] > 0x62` refuses), not a Serpent Sword (0x10c) without its flag, and `exp (+0x14) < GetWeaponMaxExp(weapon)`; effect = one **level up** with the weapon's current attachments (`WeaponLevelUpValueCalc(w, tmp, 1)`, D.3), level + 1, attachments cleared. (The Upgrade command on the Weapon page does the same but consumes a powder only if exp < max, D.4.)
* Auto Repair Powder (0xb7) is placed in a quick slot; when an equipped weapon would break (`BattleSubWeaponDmg`, native-plan) it is consumed and the weapon repaired (needs the port's weapon-wear code).

### C.4 Weapon page (`WeaponMenuSelect @0x1fcdf0` = outer state, `WeaponSelectKey @0x1fdf20` = pages; `WeaponMenuDraw @0x200c80`)
Screen: a horizontal strip of the character's weapon slots (10 shown, `DAT_01d9ea74` cursor 0..9; slot scroll `WeaponPos = -0xd6 * slot + 0xe8`), the 3D weapon model of the selected weapon (`StartReadWepMDS`, `EnterWeaponModel`; weapon model packs `commenu/weapon/`), a stat board (`wepstatus` texture 384x512: WHp / Abs bars, Attack, Endurance, Speed, Magic, 5 element rows, 10 slayer rows, hole plates) and a command column. L1/L2 and R1/R2 (0x5 / 0xa) switch the character (6 characters; the weapon record base moves with it); left/right (0x8000 / 0x2000) moves the weapon cursor.
* **Pages** (`DAT_01d9ea72`): 0 weapon list (cross opens the command column unless the slot is empty or below the default number: beep; circle closes the page); 1 **command column** (`DAT_01d9ea90` 0..6, up/down 0x1000/0x4000; right on command 0 = discard prompt): 0 Equip, 1 Customize, 2 Attribute, 3 Repair, 4 Upgrade, 5 Status break, 6 Build-up; 2 element chooser; 3 upgrade confirm; 4 status-break confirm; 5 build-up list; 6 build-up confirm; 7 build-up requirement info (left/right = switch target); 8/9/10/11 the Customize views (attachment holes / attach board / attributes tab). Help texts: 104 Equip, 105 Customize, 106 Attribute, 107 Repair, 108 Upgrade, 109 Status break, 110 Build-up, 164 Discard.
* **Equip (cmd 0)**: refused with message 411 (id 0x1a... "Cannot disarm due to spell") when the character's status has bit 0x20 (curse) set; refused with 412 ("Cannot change arms due to weapon limited zone") when `UserStatus+0x8b10 == 10`; refused with 163 ("No characters who can arm this weapon") when the character is not in the party (`char >= UserStatus+5`); otherwise `UserStatus[0x4340 + c] = slot` (WepFrameRate anim, sound 0x17), the weapon model of that character is rebuilt (`DngWeaponEquipModelBuild`, `EquipWeaponFrame`) and for Ruby/Osmond (chars 3, 5) the main effect is reloaded (`DngWepEffectReadStart`).* **Discard (right, pad 0x2000, while the command cursor is on "Equip")**: state 0xc shows message 164 ("Discard weapon"); cross: a default weapon (`IsDefaultWeapon(id) >= 0`) -> state 0xe with message 166 ("Default weapons cannot be discarded"); Serpent Sword (0x10c) while `GetMenuHebikiriFlag() == 0` -> message 167 ("Serpent Sword wants to fight with something"); otherwise state 0xd: message 165 "Discard selected weapon?" with a Yes/No toggle (up/down/left/right 0x5000 toggles, **the cursor starts on "No"**); Yes: record cleared (`InitHaveWep`), and if it was the equipped slot the default weapon is equipped (`EquipDefaultWeapon`) with sound 1; No / circle: back. READ.
* **Repair (cmd 3)**: needs a Repair Powder (`GetNowItemNum(0xb1) >= 1`, else beep): `ItemUseFunc(.., 0xb1, c, mode 4, weapon)` (C.3), on success a powder is deleted from the bag + repair effect (`WepRecover`).
* **Attribute (cmd 2) / element chooser**: choose which of the 5 elements the weapon shows/uses (`+0x16`): `WeaponMenuCheckEnableSetElem`: the element must have > 0 points in the derived stats (`WeaponAllValueSet` result `+0x17+e`) else message 161 ("Attribute with 0 pt cannot be activated"); choosing the active one again clears it to "none" (5) unless the weapon cannot be without one (`EnableWeaponElemNone`: Ruby's weapons 0x170/0x171/0x173/0x175 and anything while the viewed character is Ruby (index 3) must keep an element: message 171 "Attribute cannot be removed"). When the points of the active element drop to 0, `WeaponMenuCheckElemValue` resets it to 5 or picks the best element.
* **Upgrade / Status break / Build-up**: D.3-D.5.
* **Customize (cmd 1)**: D.2.

The **Item page** character panel shows: face (`charaface`/`btstatus2`), life bar with current/max numbers (same gauge code as the HUD, scale in the panel: life `fptosi(...)` up to 0x7e wide), a thirst bar, defense number (`UserStatus+0x4348+4c` drawn with the number font at (+100, +0x24)), the equipped weapon icon and its name; tags for active ailments. ## D. Weapon synthesis ("Customize" / attachments), level up, status break, build-up

All formulas below are READ from `WeaponAllValueSet @0x225b60`, `PlusAttachmentVolume @0x225810`, `AttachMentValuePlus @0x235a10`, `WeaponLevelUpValueCalc @0x235c00`, `CWeaponLevelUp::SetLevelUpValue @0x236280 / SetLevelUpWeaponData @0x236770 / SetStatusBreak @0x2368d0 / SetBuildUp @0x236c30 / Step @0x237010`, `CompareBuildUpModelData2 @0x2350c0`, `EnableBuildUpModel @0x235480`, `SetWeaponBuildValue @0x235320`, `GetWeaponMaxExp @0x232080`, `GetWeaponHoleNum @0x231f10`, `CheckWeaponOptionStatus @0x20f6e0`, `GetNowWeaponRate @0x20cdd0`; the tables are VERIFIED-DATA (`python -I tools/dc/dump_items.py` writes `work/tables/{items,attach,weapons}.csv`: 124 items, 50 attach rows, 120 weapons).

### D.1 Records
* **WEAPON_HAVE** (0xf8 bytes; `UserStatus + 0x450c + 0xaa8*c + 0xf8*s`): `+0` id (s16, new ids >= 0x101; < 0x101 = empty slot; `defWeapon` = {257, 299, 314, 331, 347, 363} are the "broken" default weapons, +1 the usable default one), `+2` level (number of level-ups, 0..99), `+4` Attack, `+6` Endurance (WHp loss reduction: a hit costs `(1.5 - 0.01*endurance) * param + 0.1*wear`, native-plan), `+8` Speed (attack gauge refill), `+0xa` Magic (element damage factor), `+0xc` max WHp, `+0x10` float current WHp, `+0x14` Abs = weapon exp (max `GetWeaponMaxExp`), `+0x16` current element (0..4, 5 none), `+0x17..0x1b` element points (fire, ice, thunder, wind, holy; cap 99), `+0x1c..0x25` slayer points (dragon, undead, marine, rock, plant, beast, sky, metal, mimic, mage; cap 99), `+0x28 + 0x20 k` six attachment slots (ATTACH_LIST records), `+0xe8 + k` per-slot multiplier flag (3 = the slot's attachment counts **double**), `+0xee` status-effect flag word (bits: 1 base, 2/4 mutually exclusive, 8/0x10 exclusive, 0x100/0x200 excl., 0x400/0x800 excl. -- `CheckWeaponOptionStatus` clears BOTH of an exclusive pair), `+0xf0` int: number of SynthSpheres merged so far.
* **WEAPON table row** (0x4c bytes, ids -> row via `ComItemInfo`): `+0` max WHp, `+2` Attack, `+4` Endurance, `+6` Speed, `+8` Magic (initial record values), `+0xa` owner character (u8), `+0xb..0x10` six **hole types** (0 none, 1 normal attachment hole, 2 SynthSphere plate = accepts SynthSpheres AND normal attachments; messages 112/113), `+0x12 + 2e` element points (5 x s16), `+0x1c + 2s` slayer points (10 x s16), `+0x30` (s8) base max exp, `+0x32` (s16) max-exp increment per level (`maxExp = base + level*inc`, capped 999, `< 1 -> 99`), `+0x38` initial status flags, `+0x3c` / `+0x40` build-up target masks (D.5), `+0x44` Attack cap, `+0x46` Magic cap (the stat caps of that weapon). Holes count = number of `+0xb..0x10` bytes > 0 (`GetWeaponHoleNum`).
* **ATTACH_LIST** record (0x20 bytes; the player's list is 0x2b records at `UserStatus+0x84fc`): `+0` item id (0x51..0x83), `+2` (for id 0x5a: weapon id of the sphere), `+4` status flags, `+6` (for 0x5a: the sphere's weapon level), `+8` 4 x s16 {Attack, Endurance, Speed, Magic} bonus, `+0x10` 5 x s8 element points, `+0x15` 10 x s8 slayer points; for ids 0x5b..0x5e (Attack / Endurance / Speed / Magic attachment) the bonus is a per-item quantity stored at `+8 + 2*(id - 0x5b)` set by `SetAttachMentValue(id, slot, value 1..3)` when the item is obtained (`GetAddAttachItem(id) = id in 0x5b..0x5e`; the value shown in the message = `GetAttachVolumeForMsg`). Static rows (`work/tables/attach.csv`): 0x51-0x55 Fire/Ice/Thunder/Wind/Holy +3 of the element; 0x5a Synth Sphere (built from a weapon: D.4); 0x5f-0x6b gems: Garnet (Atk +5, fire 10, rock 10, beast 10), Amethyst (ice 10, dragon 10, mage 10), Aquamarine (ice 10, marine 10, sky 10), Diamond (all slayers +5, metal +10), Emerald (Magic +10, dragon 10, plant 10), Pearl (Endurance +10, thunder 10, undead 10), Ruby (Speed +10, fire 10, mimic 10), Peridot (Atk +5, holy 10, plant 10, beast 10), Sapphire (Magic +10, wind 10, sky 10), Opal (Endurance +10, metal 10, mage 10), Topaz (Atk +5, speed +10, undead 10, sky 10), Turquoise (ice 10, rock 10, mimic 10), Sun (Atk +10, all 5 elements +10, all slayers +3); 0x6f-0x78 the ten slayers +3 (Dinoslayer .. Mage Slayer).

### D.2 Customize (attaching) -- state machine
Pages 8-11 of the Weapon page: the weapon's holes (`DAT_01d9ea90` = hole index) on the left, a scrolling board of the 40 attach items (5 columns, `+0x84fc`) on the right, and the attribute/slayer tab (page 11, `WeaponMenuTagKey`). Pick-and-drop with cross: pick an attach item from the board, cross on a hole puts it there (swapping with what the hole held; the swapped item is now held): **a SynthSphere (0x5a) can only go to a hole of type 2**, everything else to any hole (holes of type 2 hold anything); an empty hole (`id < 1`) cannot be picked from; square (0x80) sorts the board; circle cancels: `WepAttachHaveCancel` puts the held item back. After every drop `WeaponAllValueSet(weapon, tmp, 0)` recomputes the derived stats, `WeaponMenuCheckElemValue` fixes the element index. Tabs (L/R shoulder pairs) cycle Attribute (elements) / slayers / attributes views. The board refuses more than 0x28 attach items (message 162). The attached items do **not** change the stored base values until a level up (D.3): they only add to the derived values shown/used.
* **Derived stats** `WeaponAllValueSet(src, dst, forceRate1)` (this is what combat uses: `SetWeaponAttachStatus` copies the equipped weapon's derived record into the working copy): `rate = GetNowWeaponRate(src)` = 1.5 for weapon 0x110 (Lamb's Sword) when `curWHp <= 0.2 * maxWHp`, else 1.0 (forced 1.0 when `forceRate1`); for each slot k < holes with `holeType[k] > 0`: `mult = 2 if slotflag[k] == 3 else 1`, `acc += attach[k] * mult` (shorts, elements, slayers; `trunc(float)`); flag word `|= attach.flags` for SynthSpheres whose flags are not 0/1; `dst.flags = CheckWeaponOptionStatus(flags)`; then Attack(+4) = `min(trunc(cap_attack * rate), trunc((src.attack + acc.attack) * rate))` (cap_attack = table `+0x44`), Endurance = `min(99, trunc((src+acc) * rate))`, Speed = `min(99, ...)`, Magic = `min(trunc(cap_magic * rate), ...)` (cap `+0x46`), elements and slayers `min(99, trunc((src+acc) * rate))`. (Everything else copied.)

### D.3 Level up (Abs full or Powerup Powder)
* Trigger: the weapon's Abs (`+0x14`, gained by kills in the dungeon, `weapon exp event` in native-plan) reaches `GetWeaponMaxExp`; the menu offers "Upgrade" (cmd 4, page 3 Yes/No) at any time: blocked for the broken default (message 170), level >= 99 (169), Serpent Sword without its flag (413). On Yes: if `exp < maxExp` one **Powerup Powder is used up** (`DeleteItemAfterUseItem(0xb2)`), else none; then `SetLevelUpValue(weapon)`:
  1. `acc = sum over slots k (holeType > 0, attach id > 0x50) of AttachMentValuePlus(mult, acc, attach[k])` with caps while accumulating: Attack <= table `+0x44` (default 999), Endurance <= 99, Speed <= 99, Magic <= table `+0x46` (default 999), elements/slayers <= 99; `mult` 2 for double slots; count SynthSpheres (id 0x5a) -> `fusionCount`, OR their flags.
  2. `weapon.attack += acc.attack` (cap `+0x44`), `+6 += acc` (cap 99), `+8 += acc` (99), `+0xa += acc` (cap `+0x46`), elements and slayers `+= acc` (cap 99), `maxWHp = min(99, maxWHp)`, flags `|= CheckWeaponOptionStatus(flags|1 ... )`;
  3. the attachments are consumed: all six slots cleared (`memset 0xc0`, ids set to -1 in the live record); then for the weapon's hole slots 0..4 (`SetLevelUpValue`; 0..5 in `WeaponLevelUpValueCalc`) whose hole type is > 0 and != 2: walking in slot order, **each draws `rand() % 50`; the first slot that draws 5 (2 %) gets `slotflag = 3` (its attachment will count double from now on) and the later eligible slots get flag 0**; draws stop being made after the first success (slots that are not eligible keep their old flag).
  4. when the animation ends (`WeaponMenuSelect` state 7): `SetLevelUpWeaponData`: **+1 Attack (cap), +1 Endurance (99), +1 Speed (99), +1 Magic (cap), maxWHp += 1 + rand() % 3 (99), exp = 0**, `level += 1`, `+0xf0 += fusionCount`, attach slots wiped.
  Net effect of a level up: each stat gains `sum(attachments) + 1`, max WHp +1..3, attachments gone. `WeaponLevelUpValueCalc` (powder path) gives the same sums but its max WHp step is `old + 1 + rand()%3` too, and applies the 2 % double-slot roll with `rand()%50 == 5` per eligible hole.
* Message 400 `Level upgrade to "{weapon}{n}".`; effect `CWeaponLevelUp` mode 0 (sounds 0x19..); `wlevelup.pak` effect assets.

### D.4 Status break (weapon -> SynthSphere)
Page 4 Yes: `SetStatusBreak`: builds an attach record id **0x5a** in the first free attach slot (`GetBoardSpace(0x5a)`): `+2 = weapon id`, `+6 = weapon level`, stats = **0.6 (`DAT_002a1890`) x** (Attack, Endurance, Speed, Magic, elements, slayers of the weapon's stored values) **plus 0.6 x the sum of its attached items** (`AttachMentValuePlus(0.6, ...)`), `+4 =` the weapon's flag word merged with its spheres' flags, then (Step case 5, after the animation) the weapon record is removed (`memset 0xf8`, id -1) unless it is a default weapon (`IsDefaultWeapon >= 0`), in which case it is reset to level 0 with its table values (`WepDataListToHaveCopy`); if it was the equipped weapon the default weapon is equipped (`EquipDefaultWeapon`, WeaponMenuSelect state 8). The only guard is "attach list full" (message 162 when 0x28 attach records already exist). Message 118 ("Seal 60% weapon ability to sphere", confirm), 401 ("{weapon} SynthSphere acquired"). A SynthSphere can later be attached to a type-2 hole (D.2) to pass those stats on (they count as attachment values at level up).

### D.5 Build-up (transform to another weapon)
* Candidates (`EnableBuildUpModel`): for `k = 2 .. MenuCharaWeaponMax[c]`: target id = `defWeapon[c] + k` is a candidate when (`k > 20` or bit k of the table `+0x3c` mask) and (`k <= 20` or bit (k - 20) of the `+0x40` mask); `MenuCharaWeaponMax` (0x292ba8, VERIFIED-DATA) = {42, 15, 17, 16, 16, 14} (= the number of weapon ids of each character: Toan 257-298, Xiao 299-313, Goro 314-330, Ruby 331-346, Ungaga 347-362, Osmond 363-376). A candidate is **buildable** when `CompareBuildUpModelData2(target row copied by WepDataListToHaveCopy, current weapon with derived stats at rate 1)` holds: for Attack, Magic, the 5 element points and 10 slayer points: `req = target row value`; `req >= 0 ? req <= have : have <= -req` (a negative table value is an upper bound). The list shows 5 targets (page 5): buildable ones normal, unbuildable ones in red (message 172 "Items still required for buildup are indicated in red"; page 7 shows the missing items: message 173).
* Weapon 0x116 / 0x117 (Mardan Eins / Twei): special: buildable only when `GetFishMardanGarayanNum() >= table[id]` (fish count), the result is id + 1, and the counter is cleared (`ClearFishMardanGarayanNum`).
* Refused with message 168 when any attachment is still in a hole ("Build-up not allowed with attachment equipped"); level 99 / default rules as above.
* Result (`SetWeaponBuildValue` + Step case 8): `Endurance = max(old, target.endurance)`, `Speed = max(old, target.speed)`, `maxWHp = max(old, target.maxWHp)`; Attack, Magic, elements, slayers are **kept**; `id = target`, `level = 0`, `exp = 0`, `flags |= DefaultWeaponOptionSet(target)`; message 402 "Build-up to {weapon}". Weapon model/effects reload (`buildup.chr`).

## F. Port hints, bugs found, open questions

* **Bug in `native/dccore/src/text.cpp` (and `tools/dc/mesdump.py`)**: only `short[0] / 2` of the message table entries are read; the real count is `short[0]`. `_systeme.bin` loses ids 377..3079 (everything after the item names), `allmenu.mes` loses ids 541..793 (weapon / item / attach descriptions). Fix: iterate `i < short[0]`.
* Weapon stats: the working copy used in combat must be `WeaponAllValueSet(equipped record)`: stored base + attachments x (1 or 2) with caps, x1.5 for Lamb's Sword at <= 20 % WHp (D.2); it is recomputed on equip, after every hit (durability changes) and on character switch (`SetWeaponAttachStatus` callers: `BattleSubWeaponDmg`, `selectChrUnit`, `SwordDmgCheck1`, `MoveChara`). The port's `make_weapon` has no attachments / holes / double-slot flags yet.
* Not decoded / unresolved: exact `ValuePrint` row use other than row 0; the `DAT_01dc44cc` attack-gauge flag meaning; minimap marker meanings (INFERRED); floor banner Japanese branch; the pixel layouts of the Item / Weapon / Allies pages (only elements, rules and the primitives are given; rect extraction with `rects.py` misses calls that pass rectangles through helper structs, use the primitives table); `ItemMenuMainKey`'s square-button branch (tidy board?) and the active-slot pickup code paths in detail; build-up target lists per weapon (derive from `work/tables/weapons.csv` masks: bit k of `+0x3c` for k <= 20, bit k-20 of `+0x40` above); exp per kill; which button is START in the dungeon (pause).
* **More port bugs / corrections** (from the companion notes): item / weapon NAME message = `ComItemInfo[row].short@+6 + 100` for every id > 0x50 (`item_text_id_name` with `id - 156` is wrong for weapons >= 0x115); item ids 1..0x50 are aliases of weapons 0x101..0x150; the town clock in `native/gdext/src/dc_townwalk.cpp` adds 0.0011133 per tick unconditionally but the game halves it with the default time-progress option (config +0x0c == 0); the shop has no price formula (table `0x291A3C`, sell = buy/2 for items, buy/4 for weapons, weapons also sell for their attached items' sell prices).
* Tools written: `tools/dc/{ui_dump,ui_view,rects,hud_mock,mem,decomp_index,menu_mes,dump_items}.py` (+ `pak_ls.py` by the screens agent); generated tables in `work/tables/*.csv` and PNGs in `work/ui/`.
