# Item shop, check-in (charge) shop, Atla menu, inventory limits (Dark Cloud USA, SCUS-97111)

Research for the native port (2026-10-19). Sources: `work/decomp/all_dun.c` (main ELF 0x1e6800-0x1f2000 shop code, 0x1ea7a0 charge shop, 0x218000-0x21e000 Atla menu, 0x22e000-0x232000 shared "personal board"), data read with `tools/dc/mem.py`, texts with `tools/dc/menu_mes.py`.
Tags: **VERIFIED-DATA** (read from a data table / file), **READ** (read from decompiled code or disassembly), **INFERRED** (reasoned, not proven).
Pad masks (see `notes/menus.md`): 0x40 cross = OK, 0x20 circle = cancel, 0x10 triangle, 0x80 square, 0x1000 up / 0x2000 right / 0x4000 down / 0x8000 left, mask 5 = L1|L2, mask 0xa = R1|R2, 0x60 = cross|circle, 0xf060 = any d-pad|cross|circle.
Helper tools written for this note: `tools/dc/shop_dump.py` (shop table with names), `shop_prices.py` (price table), `shop_items.py` (ITEM_LIST flags/values of ids 0x84-0xff), `shop_npcs.py` (which event scripts open which shop), `atla_dump.py` (Atla boards/chips with texts).

## 0. Two corrections found on the way

1. **Item/weapon name message** (`GetWeaponMsgNo` @0x22a7e0): name = `_systeme.bin` message `ComItemInfo[(id-0x51)*8 + 6 (short)] + 100` for **every** id > 0x50. For items/attach ids (0x51-0x100) that equals `id + 100`; for weapons it is a separate sequence: weapons 0x101-0x114 happen to equal `id - 156` but from 0x115 on it does NOT (e.g. 0x12b `WoodenSlingshot[` = msg 121 where `id-156` gives 143; 0x16d `Jackal` = msg 172 where `id-156` = 209 does not even exist; 0x176 `Snail` = msg 382 where `id-156` = 218 is `MetalBreaker`). `dccore/text.cpp item_text_id_name` (`item_id - 156`) is wrong for those; use the ComItemInfo short at +6. READ + VERIFIED-DATA (`tools/dc/shop_dump.py msgno`). Description text = same short + 500 in `itemshop.pak:itemshop.bin` (e.g. msg 692 Gold Bullion, 501 `Dagger[`).
2. **Item ids 1..0x50 are weapon aliases**: `GetCommonItemInfo` maps id 1..0x50 to ComItemInfo row `id + 0xaf` = the row of weapon id `id + 0x100` (so item 5 = weapon 0x105 Wise Owl Sword; `_SITEM_CHECK_ALL(5)` in the Matataki script means "has the Wise Owl Sword"). The shop treats any shop-list id < 0x51 as an empty slot. READ.

Kinds (`WhatIsKindofItem` @0x231e20): ComItemInfo type byte 0 -> kind 2 (attach / synthesis material, `AttachList`), 1 -> kind 0 (normal item, `ITEM_LIST`), 2 -> kind 1 (weapon). Tab numbers of the boards: 0 items, 1 weapons, 2 attach. READ.

### 1.3 Prices -- no formulas, no modifiers (READ + VERIFIED-DATA)
* `CalItemMoney(id, mode)` = 0 if id < 0x51 else `GetItemMoney(id, mode)` = **short at `0x291A3C + id*4` (mode 0 = BUY) or `+2` (mode 1 = SELL)** (`GetItemMoney` @0x1e6ef0; the `ext_func_info + 0x19c` of the decompile is this table; it covers id 0..0x178 and ends where `ItemShopList2` starts). Dump: `python -I tools/dc/shop_prices.py` (id, name, buy, sell).
* **Weapon sell price = table sell price (`CalItemMoney(id,1)`) + sum of the sell prices of the up to 6 attach items fitted in the weapon record** (`WeaponCalMoney`: slots at record +0x28 + k*0x20, k < 6, id > 0x50; same mode as the caller). Buying uses the table buy price (+ attach sum, 0 for shop stock). **Durability, level, exp and the +/- flags do not change the price.** Minimum 1 gold for displaying/using a sale. READ.
* The table is fixed: no per-shop factor, no change with Georama/town progress, no rounding. Callers of `GetItemMoney`/`CalItemMoney` are only the shop functions. READ (callers checked).
* Patterns in the data: items and chips (0x51-0x5e, 0x6f-0x78) sell for **buy/2** (300 -> 150); gems 0x5f-0x6a buy 3000 sell **600 (buy/5)**, 0x6b Sun 5000 / 1000; weapons sell for **buy/4** (Baselard 300 -> 75, Gradius 500 -> 125, Wise Owl Sword 2500 -> 625). **Gold Bullion (0xc0): buy 1000, sell 1000** = "Item price no change. Good buy w/ extra $" (itemshop.bin msg 692) is purely this table row; no code. Entries with buy 2 / sell 1 are unused dummies. VERIFIED-DATA.
* Selected prices (buy/sell): Regular/Tasty/Premium Water 10/5, 30/15, 60/30; Bread 20/10; Premium Chicken 130/65; Cheese 60/30; Stamina Drink 300/150; Antidote Drink 80/40; Sacred Water 120/60; Soap 100/50; Mighty Healing 300/150; Bomb 80/40; Stone 4/2; gems (0xa1-0xa5) 100/50; Repair 20/10; Escape 20/10; Stand-in 50/25; Revival 100/50; Auto Repair 200/100; Powerup 1000/500; Pocket 100/50; Fruit of Eden 800/400; Gourd 500/250; Treasure Key 800/400; Fishing Rod 500/250; fish bait 300-450; Dran's Feather 50/25; Flapping Fish 180/90; Ice 20/10; Tram Oil/Sun Dew 300/150; amulets 380-440; character foods 1000/500; Wise Owl Sword 2500/625. Everything else: `shop_prices.py`.
* Bought stock values: `ItemDataToHaveCopy` (0x2326c0) gives the value stored with a bag item = ITEM_LIST short +0xa (water amount, hp, ...) for ids 0x84-0x100; Dran's Feather (0xeb): `(rand()%0x168, +0xb4 if < 0xb4) * 60` = 10800..21540 (3-6 minutes at 60 Hz); amulets 0x84-0x87: `rand()%5 + 3` uses; weapons: `WepDataListToHaveCopy` (record from `WeaponList`; non-default weapons get a 1 % chance of flag 0x200 (half wear) and 1 % of 0x100 (double wear) from `rand()%1000`, `<10` / `>0x3dd`). The roll is made when the shop slot is (re)initialised. READ.

### 1.4 Data structures of the shop UI (READ)
* `ShopListPt`: 30 slots x 0xfc bytes: `+0 short id`, `+4` copy of the item value (kind 0: short at +0x12 of the 'have' struct) / 0x20-byte `ATTACH_LIST` / 0xf8-byte `WEAPON_HAVE`. `ShopBoardInfo[30]` state per shop slot: **0 empty, 1 shop stock, 2 item the player put there to sell**. Player boards `ItemBoardInfo[100]`, `WeaponBoardInfo[60]` (6 characters x 10), `AttachBoardInfo[40]`: **0 empty, 2 owned (set by `ItemPosInfoInit`), 1 staged purchase (taken from the shop, not paid yet)**.
* Held item (`ShopHaveItemPt`, `IHAVEITEM`): `+0` origin state (1 from shop board, 2 from player board), `+4` kind, `+8/+0xc` source position, `+0x10 short` id, `+0x12 short` value; plus a held weapon record (0xf8) and attach record (0x20).
* Money = `UserStatus + 0x4346` (ushort). Shop stock slots are **never removed on purchase** (quick buy copies the slot) -> unlimited stock; `ItemShopGoodInitialize(shop)` (rebuilds all 30 slots from the table, re-rolls the random values, calls `ShopSpecialFunc`) runs at open and after every checkout.

### 1.5 UI state machine (`ItemShopKey2` @0x1eed70; state = `DAT_01d90250`, focus = `DAT_01d900d2`: 0 shop board, 1 player board, 2 side button "Check"; board tab = `DAT_01d900dc` 0 item / 1 weapon / 2 attach, changed with L1/L2 (5) and R1/R2 (0xa) on the player board) READ
* Layout/focus: shop board 5 columns x 6 rows (30 slots) with 4 rows visible and scrolling; the player board also 5 columns, size `PersonalRetMax(tab)` = bag size (+0x4360) / 60 / 40 (all 6 characters' weapons, 10 shown per character). Left from col 0 of the player board / right from col 4 of the shop board switch focus; Down from the last shop row goes to the Check button (focus 2); Right/Left on the button go to the player/shop board. D-pad auto-repeat: `SetAutoRepeat(pad, 0xf000, 0x1e, 5)` (30 frames, then every 5).
* Inputs in state 0:
  * **Cross on a board slot**: pick up / swap with the held item (`PersonalBoardItemGetorSwap`, shop `ItemShopSelectKey2`). Stock slot -> hand -> a player slot = staged purchase (state 1); player item -> shop slot = staged sale (state 2). Cross on the trash can with a held item that `IsEnableTrushThrow` allows and whose origin is not the shop (`*Have != 1`) throws it away (no money). A Repair/Powerup powder (0xb1/0xb2) taken from the shop cannot be dropped on a weapon slot (beep).
  * **Circle**: with a held item puts it back (`PersonalBoardItemCancel`); with empty hands: focus 0/1 -> focus 2; focus 2 -> `CheckBuyItemFunc2` result: bit 1 only (nothing staged) -> state 0x18 ("Are you leaving?"), bit 2|4 (something staged) -> state 6, bit 8 -> state 10.
  * **Triangle** on a shop slot = **quick buy** (one item): refused (beep) if the slot is empty/<0x51, if the hand is full, or if the board slot is a staged sale; **money < buy price -> state 0x15; no free place (`GetBoardSpace < 0`) or `count >= capacity` -> state 0xb**; else state 0xd (confirm). Capacity counts: items = bag size (`+0x4360`), weapons = **10 per character** (owner = `WeaponList` byte +10), attach = **40**; items already staged on the shop board still count (they would come back). State 0xd (confirm = cross or triangle, mask 0x50; circle cancels): X pays `CalItemMoney(id)` (gold clamp), copies the slot into the first free player slot with state **2** (committed at once), animates (`ShopIconMove`), calls `ShopSpecialFunc`, shows the "Thank you" talk; O -> back.
  * **Triangle** on a player item = **quick sell**: refused unless the item may be traded (rules below); price = `CalItemMoney(id,1)` (+`WeaponCalMoney`), min 1; `money + price > 0xffff` -> state 0x16; else state 0xe (confirm with cross or triangle: removes the item (record memset), adds the money clamped to 0xffff, board state 0; O back).
  * **Square**: tidy the current player board (`SeitonShopItemBoard`: 9 cycling sort orders for items, 5 for attach via `CompItem1`/`CompAttach1`; each press uses the next order that changes something) READ; no sort for weapons.
  * **Cross on the Check button** (`CheckSideKey2`): total = money + sell sum - buy sum (`SellMoneyCheck2`, `BuyMoneyCheck2`): `< 0` -> state 0x15 (not enough money); `>= 0x10000` -> 0x16; nothing staged -> 0x17; bag over capacity (`bit 8`) -> state 10; else state 0xc (confirm). Left/up from the button returns to the shop board, right to the player board.
* **Tradeable? (`IsEnableCharge(id)` @0x1e7840 + flags)** -- applies to sell, to staging a sale, and to the check-in shop: id <= 0x100: allowed unless id == 0xf2 (Moon Orb); for ids 0x84-0x100 not allowed if `ITEM_LIST short +8 & 0x10` (the key-item flag: Pocket/Fruit of Eden/Gourd 0x11, all 0x18 key items: crests, keys, maps, Fishing Rod (also hard-coded 0xb9), Candy, Red Berry, ...) -> state 4 ("You might need that one"). Weapons (id >= 0x101): allowed only if the owner still has his default weapon id (`GetDefaultWeaponNo`) or +1 in one of his 10 slots, **or the owner is not in the party yet** (`status+5 - 1 < owner`); never while another item is held; **a character's default weapon (and its broken +1) cannot be sold** (`IsDefaultWeapon(id)` == the owner -> state 4); weapon 0x10c Serpent Sword only if `GetMenuHebikiriFlag` (game flag 0x30) is set; **the weapon currently equipped by that slot** (`status+0x4340+char == slot`) -> state 5 ("You're already equipped with that"). VERIFIED-DATA for the flag column (`shop_items.py`).
* Other states: 1 fade-in (frame counter `DAT_01d90254`, alpha +8/frame, ready after >0x14 frames), 2 exit fade (alpha -8, returns 1 when counter > 0x1a and alpha 0), 3 greeting (waits for 0xf060), 4/5/7/0x15/0x16/0x17/0xa/0xb/0x14/0x19 message states that wait for 0x60 (cross|circle), 6 / 0x18 / 0xc / 0xd / 0xe with X/O choices (0x18: X = continue (state 0), O = state 0x19 "Come visit again" then any button -> state 2 exit; 0xc: X = `IncludeBuyItem2` (commit, money += sells - buys, `ItemShopGoodInitialize`, state 0x14), O back; 6 "Return / Take": O = `ShopCancelGoodReturn2` (give everything back), X = back to browsing (the exact next state arguments are INFERRED)). `ExitItemShop2` always runs `ShopCancelGoodReturn2` (staged items go back) and, in shop 1, sets game flag 200 if the player owns item 5.
* Checkout commit: `IncludeBuyItem2` -> money = clamp(money + SellMoneyCheck2 - BuyMoneyCheck2, 0xffff); sold items deleted from the shop board, staged buys become owned (state 2).
* Quantity/limits: **gold cap 0xffff (65535)** everywhere (ushort); bag size byte `UserStatus+0x4360` (init 50 = 0x32, max 100, section 4); weapon slots in the shop 10 per character (record slot count in the save is 11); attach 40 (record array 0x2b); item/attach "stack" does not exist: each slot is one item (the short at `+0x443c` is the item's own value, e.g. water amount, uses, Feather time).

## 4. INVENTORY LIMITS (READ; the bag code itself is already ported in `native/dccore/src/items.cpp`)
* **Bag**: `UserStatus + 0x4360` = capacity byte (initial **50**, `Initialize` @0x1bf340 line 108572; max **100**), item ids short[103] at `+0x436e` (100 + 3 spill-over), values at `+0x443c`; three active (quick) slots ids at `+0x4362`, counts at `+0x4368` (a quick slot stack counts `count` times toward the capacity). **Pocket (0xb3)**: usable only while capacity < 0x60 (96): capacity += ITEM_LIST short +0xa (= 10 for Pocket), clamped to 100, new slots set to -1 (message 407 "Can now carry {n} Items."); events can do the same (`_ADD_MAXITEM(n)` / `_ADD_MAXITEM_MES`: `EdAddMaxItem`, clamp 0..100).
* **Capacity count** (shop, check-in, `GetNowModeMaxNum`): occupied slots with id >= 0x84 among the first `capacity + 3` + sum of the quick-slot counts; over capacity sets the overflow flag `+0x431c` (item goes to a spill slot) and the dungeon forces the item menu (`gameTask 0x1e`) until the bag fits (overflow slots are marked as trash-marked, `SetMenuTrushMark`). Ids 0xe9, 0xea, 0xee (Map, Magical Crystal, Worldmap) are never stored (always accepted); attach limit **0x28 = 40** (record array 0x2b entries, overflow when >= 0x29); weapons **10 per character** (11 records, the 11th = overflow slot; `CheckItemGet`, `GetNowModeMaxNum` kind 1 counts 11). Summary of `check_item_get`: 0 = room, 1 = bag full (items 0x84-0x100), 2 = attach list full (0x51-0x83).
* **Gold** `UserStatus + 0x4346` ushort, **cap 0xffff** (`add` sites clamp to 0xffff; shop warns at overflow); halves on game over (`SetDead` `>> 1`, escape item keeps it), a monster hit with status bit 0x40000 (20 % chance) steals 1/5 of it when you hold more than 10.
* **Trash** (`ItemTrushKey` @0x201e30 in the dungeon menu, shop/check-in `IsEnableTrushThrow(id)` @0x2311a0): never throw while another item is held; items 0x51-0x100: kind item -> allowed iff `ITEM_LIST short +8 & 0x10 == 0` (key items 0x18/0x11 cannot be thrown), attach items always; weapons: allowed only if the owner still has his default weapon (id or +1) in one of his slots (so a character always keeps a weapon) or is not in the party, and not the Serpent Sword 0x10c without game flag 0x30; the dungeon `ItemTrushKey` additionally refuses any character's default/broken-default weapon (`GetDefaultWeaponNo`) and equipped slot. The can: `CommonTrushDraw`, hint text `shopman.bin` +40 / `itemshop.bin` msg 1000 "Trash Can: Discard items.".
